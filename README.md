# Архитектура sc-sdk

## Стек

- react 18
- Zustand

## Описание

Платформа чатов, которая является частью других проектов платформы:

- web
- webview (ios, android). В таком случае данные передаются через мост

## Подключение

Для приема-отправки сообщений есть 2 режима:

- коммуникация через мост. В таком случае хост-приложение (webview) транслирует данные (например, список сообщений) в sdk. При отправке нового сообщения оно передается назад через мост
- работа через http и websocket. Хост передаёт адрес для получения endpoint'ов с первоначальнымим access и refresh токеном с обновлением через dpop заголовок. Ответственность клиента своевременно обновлять токены

### Последовательность

- Получить config с feature flags приложения (по сети или явно объектом)

для работы по сети 

- получить адреса endpoints
- запросить данные 

Каждый следующий http запрос будет содержать новый dpop, который потребуется пробрасывать заголовком в последующий

## Endpoint'ы

Используются для 

- загрузки файлов
- получения истории сообщений

## Модели

- surface, поверхность или хост-приложение со своими настройками
- threads (ветки) - в зависимости от настроек поверхности, поддерживается от 1 до бесконечности чатов
- message - сообщение в ветке
- top banner - одно постоянное уведомление (не сообщение) сверху в ветке
- file - файл, который может быть прикреплён к сообщению

## Поставщики данных 

Поддерживают двустороннюю коммуникацию

- Bridge - данные поступают от моста webview
- network: websocket + http (rest). REST загружает первоначальную конфигурацию, а также историю сообщений, ws используется для общения отдельными сообщениями в рамках сессии. Обычно два этих способа - части одной стратегии (см Подключение), но для упрощения можно и разделить на отдельные части (если это упростит)

- Local - оптимистичные сообщения. то, что пользователь написал и отправил лично

## Возможные идеи

ООП стиль единого движка ленты чатов, к которому подключаются адаптеры и стратегии авторизации

## Требования

- модульная расширяемая архитектура
- аккуратно относимся к фундаментальному подходу и over engineering. Это сложно внедрять, сопровождать, обучать
- простой DX (думал о хуках для middle разработчиков как фасадах)
- Защита от дурака или, напротив идемпотентность при обращении с разных частей приложения:
  - через setter'ы Zustand
  - через providers
  - через instance движка ленты чатов
  при этом надо учитывать, что двусторонняя коммуникация может привести к лавине из-за цикла взаимных подписок
- избежать велосипеда, который будет сложно поддерживать
